# Database Migration Workflow

This document outlines the database migration workflow for the Pawnshop Management System using Alembic with Context7.

## Context7 Approach

Context7 is a structured approach to database migrations that categorizes migrations into 7 contexts:

1. **Schema** - Database schema changes (tables, columns, constraints)
2. **Data** - Data migrations and transformations
3. **Indexes** - Index creation and optimization
4. **Functions** - Database functions and stored procedures
5. **Views** - Database views
6. **Triggers** - Database triggers
7. **Permissions** - Database permissions and grants

This approach helps organize migrations and makes it easier to understand the purpose of each migration.

## Migration Workflow

### 1. Creating a New Migration

To create a new migration, use the Context7 utility:

```python
from app.db.context7 import Context7

# Create a new schema migration
Context7.create_migration("add_user_table", "schema")

# Create a new data migration
Context7.create_migration("seed_default_roles", "data")

# Create a new index migration
Context7.create_migration("optimize_customer_search", "index")
```

This will generate a migration file with the appropriate prefix in the `migrations/versions` directory.

### 2. Running Migrations

To apply migrations:

```python
from app.db.context7 import Context7

# Upgrade to the latest migration
Context7.upgrade()

# Upgrade to a specific migration
Context7.upgrade("revision_id")
```

Or use the Alembic CLI:

```bash
# Upgrade to the latest migration
alembic upgrade head

# Upgrade to a specific migration
alembic upgrade revision_id
```

### 3. Downgrading Migrations

To revert migrations:

```python
from app.db.context7 import Context7

# Downgrade one migration
Context7.downgrade()

# Downgrade to a specific migration
Context7.downgrade("revision_id")

# Downgrade all migrations
Context7.downgrade("base")
```

Or use the Alembic CLI:

```bash
# Downgrade one migration
alembic downgrade -1

# Downgrade to a specific migration
alembic downgrade revision_id

# Downgrade all migrations
alembic downgrade base
```

### 4. Checking Migration Status

To check the current migration status:

```python
from app.db.context7 import Context7

# Show current revision
Context7.current()

# Show migration history
Context7.history()
```

Or use the Alembic CLI:

```bash
# Show current revision
alembic current

# Show migration history
alembic history
```

## Best Practices

1. **One Change Per Migration**: Each migration should focus on a single change or a set of closely related changes.

2. **Use Appropriate Context**: Categorize migrations correctly based on their purpose.

3. **Test Migrations**: Always test migrations in a development environment before applying them to production.

4. **Include Downgrade Logic**: Ensure each migration has proper downgrade logic to allow rollbacks.

5. **Document Complex Migrations**: Add comments to explain complex migrations, especially data migrations.

6. **Version Control**: Always commit migration files to version control.

## Migration Sequence

For a new project, follow this sequence for migrations:

1. **Schema Migrations**: Create tables, columns, and constraints
2. **Index Migrations**: Add indexes for performance
3. **Function/View/Trigger Migrations**: Add database functions, views, and triggers
4. **Permission Migrations**: Set up database permissions
5. **Data Migrations**: Seed initial data

## Troubleshooting

### Migration Conflicts

If you encounter migration conflicts (multiple heads), you need to merge the migrations:

```bash
alembic merge heads -m "merge_migration_name"
```

### Failed Migrations

If a migration fails:

1. Check the error message
2. Fix the issue in the migration file
3. Run `alembic upgrade head` again

If you need to revert a failed migration:

```bash
alembic downgrade -1
```

### Autogenerate Issues

Alembic's autogenerate feature may not detect all changes. Common issues include:

- Enum type changes
- Constraints and indexes with custom names
- Table or column name case changes

Always review autogenerated migrations before applying them.
